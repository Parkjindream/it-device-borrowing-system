# 1. บทนำและเป้าหมายของระบบ

## 1.1 ความสำคัญและความเป็นมาของปัญหา

สถานศึกษามีอุปกรณ์ไอทีกลาง (โน้ตบุ๊ก กล้อง ไมโครโฟน ฯลฯ) ให้นักศึกษายืมใช้ แต่การจัดการด้วย **สมุด/ไฟล์ Excel** มีปัญหาซ้ำ ๆ คือ

1. **ของซ้ำ/ของชนกัน** — สองคนจองของชิ้นเดียวกันพร้อมกัน เพราะไม่มีการตัดสต็อกแบบเรียลไทม์
2. **ตามของยาก ของหาย** — ไม่รู้ว่าใครถืออุปกรณ์ชิ้นไหนอยู่ เลยกำหนดคืนแล้วยังไม่คืน
3. **ไม่มีการแจ้งเตือน** — ผู้ยืมลืมกำหนดคืน เจ้าหน้าที่ต้องไล่ทวงเอง
4. **ไม่มีบทลงโทษที่บังคับใช้จริง** — คืนช้าไม่มีผล ทำให้คนอื่นไม่ได้ใช้ของ
5. **ตรวจสอบย้อนหลังไม่ได้** — ไม่มีประวัติว่าใครยืม-คืนเมื่อไร สภาพอุปกรณ์ตอนส่ง-รับเป็นอย่างไร

ระบบนี้จึงถูกออกแบบมาแก้ปัญหาข้างต้น โดยยึดแนวคิดหลัก **"จองเป็นชิ้น (unit) ไม่ใช่จองเป็นรุ่น"** — ทุกเครื่องมีหมายเลขทรัพย์สิน (serial number) ของตัวเอง ทำให้ตามของได้ถึงระดับชิ้น และตัดสต็อกได้แม่นยำ (ดูเหตุผลการออกแบบใน `backend/SCHEMA_NOTES.md`)

## 1.2 วัตถุประสงค์

1. ให้ **นักศึกษา** จองอุปกรณ์ออนไลน์ เห็นจำนวนคงเหลือจริง และรับการแจ้งเตือนกำหนดคืนทางอีเมล
2. ให้ **เจ้าหน้าที่** จัดการคลังอุปกรณ์ ยืนยันการรับ-คืน และคุมบทลงโทษจากที่เดียว
3. **ป้องกันการจองชนกัน (race condition)** ด้วยการควบคุมที่ระดับฐานข้อมูล ไม่ใช่แค่เช็คในโค้ด
4. เก็บ **ประวัติการยืม-คืนเป็นหลักฐาน** ลบทิ้งไม่ได้ง่าย ๆ (ใช้ `on_delete=PROTECT`)
5. ออกแบบให้ **ปลอดภัย** และ **ติดตั้ง/ทำซ้ำได้ด้วยคำสั่งเดียว** (Docker Compose)

## 1.3 ขอบเขตการทำงาน (Scope & Capabilities)

ระบบแบ่งเป็น 7 โมดูล (ใช้รหัส A–G ตรงกันทั้งในโค้ด คอมเมนต์ และ URL):

| โมดูล | ชื่อ | ขีดความสามารถหลัก |
|:---:|------|------------------|
| **A** | บัญชีผู้ใช้ (Authentication) | login/logout, ดู/แก้โปรไฟล์ตัวเอง, เปลี่ยนรหัสผ่าน, ขอลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล, 2 บทบาท (นักศึกษา/เจ้าหน้าที่) |
| **B** | คลังอุปกรณ์ (Inventory) | ดูรายการ/ค้นหา/กรองตามหมวด + จำนวนคงเหลือสด, หน้าสาธารณะไม่ต้องล็อกอิน; เจ้าหน้าที่เพิ่ม/แก้/ปิดใช้งานรุ่นอุปกรณ์และจัดการชิ้น (auto-gen serial) |
| **C** | การจอง (Booking) | นักศึกษาจอง (1 คน 1 รายการที่ยังไม่จบ), ยกเลิกตอนรอรับ, ลบ/เคลียร์ประวัติ |
| **D** | รับ-คืน (Pickup/Return) | เจ้าหน้าที่ค้นด้วย QR (อ่านอย่างเดียว), ยืนยันรับ, ยืนยันคืน (ติดธงชำรุด → ปิดใช้งานชิ้นนั้น) |
| **E** | แจ้งเตือน (Notification) | ส่งอีเมลทุกเหตุการณ์สำคัญ + เก็บ log การส่งทุกครั้ง |
| **F** | บทลงโทษ (Penalty) | คืนช้าเกินเกณฑ์ → พักสิทธิ์จองอัตโนมัติ, เจ้าหน้าที่ปรับค่าปรับ/ปลดล็อกได้ |
| **G** | ภาพรวม (Dashboard) | สรุปตัวเลขให้เจ้าหน้าที่ (คำนวณสด) |

**งานอัตโนมัติเบื้องหลัง** (โปรเซสแยก `run_scheduler`): ยกเลิกการจองที่ไม่มารับตามเวลา (no-show), ปลดพักสิทธิ์เมื่อครบกำหนด, ส่งอีเมลเตือนใกล้ครบ/ถึงกำหนด/เกินกำหนด (กันส่งซ้ำในวันเดียวกัน), ลบข้อมูลเก่าตามนโยบายเก็บข้อมูล

**นอกขอบเขต (ตั้งใจไม่ทำในเฟสนี้):** ระบบชำระค่าปรับเป็นเงิน, แอปมือถือ native, การยืมข้ามวิทยาเขต, การเชื่อมระบบทะเบียนกลางของสถาบัน
